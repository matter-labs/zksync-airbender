# Blake2Round span witness generators

Write the index-by-index modules of the extended-control Blake2s round non-vacuity witness
(`proven/Proven/NonVacuous/Blake2RoundSpan/`, the honest row's `Row.holds`): one private lemma per imported query or
equation, with the tactic its kind needs, and a dispatcher per module. Each generated module starts with a
`-- Generated by …; do not edit by hand.` line. Only needed when the round circuit artifact or the honest row
(`Honest.lean`) changes; the hand-written modules (`Honest`, `Columns`, `GHonest`, `*Trace`, `Queries`, `Tables`,
`FinalEval`, `AssertEval`, `ScheduleAsserts`, `Row`, `Block`, `Ports`, `Steps`, `Span`) hold the tactics and lemmas
the generated proofs call.

| script | writes | covers |
|---|---|---|
| `g_calls.py` | `ColumnLookups0-3`, `DiagonalLookups0-3` | lookups 2–129: the sixteen queries of each G call |
| `final_xor.py` | `FinalLookups0-7` | lookups 130–193: the final XOR, one module per chaining word |
| `asserts.py` | `Asserts{Control,Products,Chaining,Lanes,Writeback,Carries,FinalBits,BorrowsLow,BorrowsHigh}` | constraints 0–73, 106–219 |
| `timestamps.py` | `Timestamps0`, `Timestamps1`, `Alignments` | the 89 timestamp queries; lookups 0–1 |

Inputs: none but the output directory. The query and constraint indices, column numbers and slot layouts are
constants in the scripts, read off the imported circuit
(`cs/compiled_circuits/blake2_with_extended_control_layout_no_caches_gkr.json`, as `importedConstraints.lookup_k` /
`constraint_k` state them); a wrong constant fails the Lean build of the generated module. No network.

From `cs_formal_verification/lean`:

    python3 -I gen/nonvac/blake2round/g_calls.py proven/Proven/NonVacuous/Blake2RoundSpan
    python3 -I gen/nonvac/blake2round/final_xor.py proven/Proven/NonVacuous/Blake2RoundSpan
    python3 -I gen/nonvac/blake2round/asserts.py proven/Proven/NonVacuous/Blake2RoundSpan
    python3 -I gen/nonvac/blake2round/timestamps.py proven/Proven/NonVacuous/Blake2RoundSpan

Then rebuild `Checks.Satisfiable` (or run `./verify.sh`). The output is deterministic: rerunning reproduces the
committed modules byte for byte.
