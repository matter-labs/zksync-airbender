# Verification status

The single model is `cs_formal_verification/`. The statements use the shared constraint
description, current cached captures, CleanCore and Lean 4.35. The native machine
corollaries reach complete RV runs and configured Airbender machine runs. They include
ordinary instructions, modular operations and matched standard and split workers.

Every public statement has a final proof. Each universal claim has a separate witness for its exact premises,
except the fixed-data equations listed by exact name in [the coverage map](../lean/claim_coverage.json).
[The coverage checker](../lean/scripts/check_claim_coverage.py) reads every constant of `human/` whose name ends in
"Claim". Each one must be a definition of type Prop, with a final theorem in `proven/Proven/Final/` and a row in the
table below. The witness of a claim must be `<stem>SatisfiableClaim`, where the stem is the claim name without
"Claim", or without "SoundnessClaim" when only that witness exists. No two claims share a witness. A Lean example in
[Satisfiable.lean](../lean/test/Checks/Satisfiable.lean) takes the claim and its witness, and applies the claim to
data that it takes from the witness. A witness statement must be an existential, and no claim joins soundness and
non-vacuity. Only the fixed-data equations of the coverage map have no witness.
The [axiom audit](../lean/test/Checks/Axioms.lean) checks proof dependencies.
The replay runs nightly from `main`, and `ci.yml` dispatches it on demand.
Lean kernel replay, its export axiom audit, the native paranoid kernel and the
Clean-module leanchecker replay are required. The external checkers are advisory. The [trust guide](TRUST_AND_REVIEW.md) states the external interfaces.

All 16 native setups have complete byte freshness checks. Trusted compiled comparisons
bind their fixed regions and the ROM fixture. Arbitrary public ROM and decoder data use
the explicit public setup binding. This does not prove the Rust generator for every
program. All 14 cached captures have arithmetic preservation and physical witness proofs.
Native worker certificates supply every worker equation, public lookup and participation flag.
Exact state, request and architectural memory matching remain explicit interfaces. A sampled field equation does not establish exact natural matching.

The [unified native premise witness](../lean/proven/Proven/NonVacuous/DynamicCopyLoop/Native.lean) has sixteen CPU rows
and two bigint COPY calls. Its cached certificates include native gates, placement, public lookups and participation.
It checks both complete public initialization windows and their terminal teardown tokens.
Each unrolled native target has a one-row ADD witness with its complete public boot and teardown contract.
The unrolled constraint-description targets and their Sail forms use the same active ADD witness.
Each padded target has exactly two CPU rows: one active ADD row and one constrained padding row.
The projection witness uses this same complete masked boundary.
The [hash-window witnesses](../lean/proven/Proven/NonVacuous/RoundWindow/Acceptance.lean) have ten active CPU callers,
ten BLAKE2 round workers and one complete window. The code-window witnesses bind the same rows to public ROM code.
Per-circuit and reference-span witnesses cover accepted rows and complete worker schedules separately.

Both unrolled targets exclude `mop.r.N`. Unified admits `mop.r.N` with N = 16, 12, 8 or 7, and `mop.r.N x0` for
every N as a no-op.
The targets use the modeled `mop.rr.N` operations. All three production targets exclude
special5. The separate valid-use claims cover bigint, G, round, hash and both Keccak
reference schedules. Native execution does not assume delegation validity.
The [Sail boundary](../lean/human/Human/ISA/Sail/README.md) lists the machine overrides.
The [findings register](FINDINGS.md) records F01-F13 and the historical AIH dispositions.
