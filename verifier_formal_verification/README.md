# zksync-airbender-fv

PoC: verify the *exact* RV32IM bytes that rustc emits for small Airbender-style Rust programs against succinct
Lean specs.

**Check everything:** `./verify.sh` (rebuilds the binary, checks the Lean copy of it, builds all proofs, checks the
final theorem's statement and axioms).

## What a human reads (`lean/human/`, ~200 lines)
- `Human/RV32.lean` — the machine: RV32IM as Airbender runs it (decoder from the encoding tables, one line of
  behaviour per instruction, memory map; anything else has no next state = unprovable).
- `Human/Call.lean` — what "this code implements a function" means (RISC-V calling convention).
- `Human/Spec.lean` — what the Rust functions should compute (`combine x = 3x + 1`, ...).
- `Human/Theorems.lean` — the final statement `ProgramCorrect`: from reset, with the image loaded and input `x`,
  the program reaches its final self-jump with `a0 = combine x` and stays there.
- `HumanSail/Airbender.lean` — the Airbender machine as the official Sail RISC-V model plus a short list of
  changes, each marked `-- Airbender:` (needs the generated Sail model, `sail/regen.sh`).
- `HumanSail/Theorems.lean` — our spec = Sail: `DecodeIsSail`, `StepIsAirbender`, and `ProgramCorrect` on the
  Airbender machine itself (checked by `verify.sh` step 5 when the Sail model is generated).
- `image/Image.lean` — generated byte copy of `build/app.bin` + symbol addresses (checked by `verify.sh`).

## Everything else (`lean/slop/`, kernel-checked, not meant to be read)
- `Slop/RV/` — symbolic execution on the RV32 spec: memory/step lemmas, generated per-word `decode` lemmas and
  code lists (`lean/gen/words.sh`), tactics, per-function proofs (`Inc`, `Double`, `Combine`), whole program
  (`Program`), link check + final proof (`Final`).
- `Slop/Sail/` — the official Sail RISC-V model route (Airbender config, oracle evaluator, `kernel_rfl`).
- `Slop/Equiv/` — our spec ⇔ Sail: decoder walk, symbolic Sail runner (`sail_run`), per-layer memory lemmas,
  per-instruction execute lemmas, `StepIsAirbender`, final transfer (`Final.lean`).

## Other
- `rust/` — Airbender-style no_std guest, build flags, `build.sh` (deterministic).
- `sail/` — scripts and pins to regenerate the Sail RV32 Lean model; `sail/fetch-lean-sail.sh` fetches the pinned lean-sail
  library (no upstream licence, so never committed; `verify.sh` runs it). The generated model (`lean/sail-rv32/SailRV32/`, ~52 MB) is
  gitignored: never commit it or any other large/generated data (this is a public repo; see `LOG.txt`).
- `lean/check.sh` — build Lean modules under the project limits (60 s, 4 GB).
- `LOG.txt` — PLAN / TODO / DONE (pick up work from here). `docs/` — design notes.
