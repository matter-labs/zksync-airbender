# zksync-airbender-fv

PoC: verify the *exact* RV32IM bytes that rustc emits for small Airbender-style Rust programs against succinct
Lean specs.

**Check everything:** `./verify.sh` (rebuilds both binaries, checks the Lean copies, builds all proofs, checks the
final theorems' statements and axioms).

The guest is built twice (`rust/build.sh`): `build/app_mop.bin` (cargo features `mop`: BabyBear ops via Airbender's
field opcodes `mop.rr.N`, and `delegation`: Blake2s by seven calls of the round-function delegation, CSR `0x7c7` —
as the real verifier) and `build/app.bin` (the same ops and Blake2s in plain Rust, trusting no opcode or delegation).
Both compute a Mersenne31 polynomial, a BabyBear Ext4 polynomial (Horner) and a Blake2s compression (the verifier's
`blake2s_u32`, 7 rounds) of their input, five words read from Airbender's non-determinism source (CSR `0x7c0`);
then a Fiat–Shamir check: the digest is the transcript seed, the challenge `z` its first four words, and the prover's
claim `v = poly4 z` (four more words from the non-determinism source) is checked — a wrong claim fails the run; then
a Merkle path from the digest to a root (root, depth ≤ 32, and per level a side word and a sibling, all from the
input; the verifier's two-to-one Blake2s hash) — a wrong root fails the run.

## What a human reads (`lean/human/`, ~200 lines)
- `Human/State.lean` — the machine state (registers, PC, byte memory, the non-determinism input).
- `Human/Delegations.lean` — Airbender's delegations (precompiles), one call per instruction: Blake2s round (`0x7c7`),
  u256 bigint (`0x7ca`), Keccak special5 (`0x7cb`) and Keccak-f1600 (`0x7cc` … `0x7ce`); `Accepted`: Airbender's
  setup accepts the binary (delegation run lengths, the 361-call Keccak-f1600 pattern). Built from `Human/Blake2s.lean` (Blake2s constants, `G`, one round) and `Human/Keccak.lean`
  (Keccak-f[1600], FIPS 202).
- `Human/DelegationRuns.lean` — what a run of calls computes, stated with those standard definitions: 7 (10) round
  calls = the 7-round (RFC 7693 10-round) Blake2s compression, or `hash2` (its 10-round version) in compression mode;
  649 special5 / 361 f1600 calls = Keccak-f[1600]; delegation words in
  ROM run as these calls. Calls outside such a run (another layout or control word) are undefined behaviour.
- `Human/RV32.lean` — the machine: RV32IM as Airbender runs it (decoder from the encoding tables, one line of
  behaviour per instruction, memory map, the input read `csrrw rd, 0x7c0, x0` from a list of input words; anything
  else has no next state = unprovable).
- `Human/Call.lean` — what "this code implements a function" means (RISC-V calling convention).
- `Human/Spec.lean`, `Human/SpecPoly.lean`, `Human/SpecExt4.lean` — what the program should compute
  (`combine x = 3x + 1`, a polynomial over Mersenne31, a polynomial over BabyBear's `F[w]/(w⁴ - 11)`), and
  `Human/SpecBlake.lean` (Blake2s compression, RFC 7693, 7 rounds), `Human/SpecFS.lean` (the challenge and the
  claim the program checks), `Human/SpecMerkle.lean` (the two-to-one hash, the root a path leads to, how the path is
  read).
- `Human/Theorems.lean` — the final statement `ProgramCorrectOf`: under its `Assumptions` (from reset, with the image
  loaded, RAM zero and an input starting with the five words and the claim): if the claim is right, the program
  reaches its final self-jump with the outputs in `a0 … a7` and stays there; if it is wrong, no run ever reaches it.
  `NonVacuousOf`: the assumptions can be met, with a right and with a wrong claim. `ProgramCorrect` (plain image) and
  `ProgramCorrectMop` combine them (both proven).
- `Human/Vectors.lean` — the standards' test vectors: Blake2s (RFC 7693) and Keccak-f[1600] give the published
  results, and the Keccak slot map matches Airbender's table (proven by evaluation).
- `HumanSail/Airbender.lean` — the Airbender machine as the official Sail RISC-V model plus a short list of
  changes, each marked `-- Airbender:` (needs the generated Sail model, `sail/regen.sh`).
- `HumanSail/Theorems.lean` — our spec = Sail: `DecodeIsSail`, `StepIsAirbender`, and `ProgramCorrect` on the
  Airbender machine itself (checked by `verify.sh` step 5 when the Sail model is generated).
- `image/Image.lean`, `image/ImageMop.lean` — generated byte copies of `build/app.bin`, `build/app_mop.bin` +
  symbol addresses (checked by `verify.sh`).

## Everything else (`lean/slop/`, kernel-checked, not meant to be read)
- `Slop/Sym/` — a verified symbolic executor for straight-line code (value DAG, soundness, side-condition checker,
  readback; `sym_block`/`sym_run` run it once in the kernel per block).
- `Slop/RV/` — proofs on the RV32 spec: memory/step lemmas, generated per-word `decode` lemmas and code lists
  (`lean/gen/words.sh`), tactics, per-function proofs (`Combine`, `Poly*`, `Memcpy*`, `Init`, `MulAddMop`,
  `MulAdd/`, `Horner*`, `Ext4Poly/`, `Ext4PolyMop`, `Blake/`, ...), `main` (`Main/`: blocks between calls, the
  whole program `Main/Run`), link check + final proofs (`FinalPlain`, `FinalMop`). Plain-Rust arithmetic: the executor's DAG is cut at the field operations
  (`lean/gen/clusters.sh`, `lean/gen/blake.sh`; cut points found by evaluation, untrusted) and each piece is proven
  (`BBPlain`, `Blake/Lemmas`).
- Interfaces that keep proofs local (a change re-proves only its own file): `RV/DecodeShape.lean` (what a decoded
  instruction looks like) and `RV/DecodeCsr.lean` (the CSR table) are the only lemmas downstream proofs use about
  the decoder besides `Equiv/Decode.lean`; `RV/Frame.lean` (a stack frame's stores as a list); `RV/Merkle/Contract.lean`
  and `RV/Merkle/MFrame.lean` (`merkle_step`'s contract, `merkle_check`'s frame), so its parts build in parallel.
- `Slop/Deleg/` — the delegation runs (`Human/DelegationRuns.lean`): Blake2s rounds by induction over the calls;
  Keccak through a slot view of the 31 lanes, one lemma per call kind, five stages per round.
- `Slop/Sail/` — the official Sail RISC-V model route (Airbender config, oracle evaluator, `kernel_rfl`).
- `Slop/Equiv/` — our spec ⇔ Sail: decoder walk, symbolic Sail runner (`sail_run`), per-layer memory lemmas,
  per-instruction execute lemmas, `StepIsAirbender`, final transfer (`Final.lean`).

## Other
- `rust/` — Airbender-style no_std guest, build flags, `build.sh` (deterministic).
- `sail/` — scripts and pins to regenerate the Sail RV32 Lean model; `sail/fetch-lean-sail.sh` fetches the pinned lean-sail
  library (no upstream licence, so never committed; `verify.sh` runs it). The generated model (`lean/sail-rv32/SailRV32/`, ~52 MB) is
  gitignored: never commit it or any other large/generated data (this is a public repo; see `LOG.txt`).
- `lean/check.sh` — build Lean modules under the project limits (60 s, 4 GB).
- `LOG.txt` — PLAN / TODO / DONE (pick up work from here). `docs/` — design notes.
