# Verification status

This is the current state, not a change log. Update it after each completed task.
**Checked** means Lean proves soundness of the imported richer no-cache constraints,
under the interfaces stated in `Review/`. It does not mean full prover/verifier soundness.
Standard instructions use pinned Sail; custom operations use the pinned project spec
or the named Clean reference. Controller claims concern explicitly modeled setup rows.
Clean is the sole constraint semantics. Fetch binding is part of the approved
restricted-subset work; interrupts and exceptions remain outside that claim.

## Machine checking

All published claims are kernel-checked. The full-family baseline has 98 importer
checks and 568 audited declarations. The focused trace targets have twenty-two
importer guards, normal/rollover and native-history/rejection/reordering fixtures,
including interleaved per-address histories and rejection of a locally valid
fabricated read value, nonzero initial-value histories and bounds, native Sail
initial-image/byte-order and missing-cell/PC fixtures, public-byte decoding and

combined address value, modeled ROM byte reads and wrong-value/missing-address
rejections, a merged history with reordered dependent instructions, native Sail
RAM/code/GPR frame fixtures, a complete accepted SW row crossing a limb boundary
and preserving its fetched code bytes across the complete native Sail history,
interleaved native register/RAM updates,
x0 and overlapping-word rejection fixtures, public-image seeded Sail execution
with interleaved repeated accesses and derived final reads, an accepted SW's complete
native Sail access history, a discarded ADD-to-x0 trace with repeated clock refreshes,
and rejection of a nonzero native x0 output, rejection of a fabricated terminal RAM value, native PC retirement preserving the
terminal RAM value, chronological grouping of reordered dependent instructions,
complete native PC-path linkage, aliased readonly refreshes, original Machine translation at the top RV32 word address and for code fetch, rejection of uninitialized access configuration, the complete Off-entry PMP walk and locked-entry rejection, aligned PMA load/store permission at RV32 boundaries and missing-region rejection, ordinary RAM read/write MMIO exclusion and recognition/rejection of native MMIO windows, original RAM roundtrip at the last RV32 word with exact byte order and rejection of a missing fourth byte, checked physical load/store at that address and the original store-address announcement, configuration preservation through native GPR/RAM/PC updates and complete histories, actual virtual LW/SW transport (including discarded LW results and zero-register stores), native decoder stability under CSR changes and fetched code preservation under RAM writes, imported-port rs1/read/write binding on a complete aliased x0 row, and 385 audited declarations.
Changed clock/port/history/path modules pass warning-as-error checks. All audited dependencies are
standard Lean axioms (`propext`, `Classical.choice`, `Quot.sound`); no `sorry` or
project axioms. See [reproduction commands](README.md#reproduce)
and [trust boundaries](TRUST_AND_REVIEW.md). The [plan](FORMAL_VERIFICATION_PLAN.md)
sets the implementation order; this document records the current coverage and gaps.
