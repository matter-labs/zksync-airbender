# Verification status

This is the current state, not a change log. Update it after each completed task.
**Checked** means Lean proves soundness of the imported richer no-cache constraints,
under the interfaces stated in `Review/`. It does not mean full prover/verifier soundness.
Standard instructions use pinned Sail; custom operations use the pinned project spec
or the named Clean reference. Controller claims concern explicitly modeled setup rows.
Clean is the sole constraint semantics. Restricted-subset claims bind actual
fetch/decoding; interrupts and exceptions remain outside that claim.

## Machine checking

All published claims are kernel-checked. The full-family baseline has 98 importer
checks and 578 audited declarations; the focused trace targets have 26 importer
guards and 657 audited declarations. Fixtures cover accepted and rejected native
histories, public initialization and Sail decoding, ordered and aliased ports,
terminal reads, code/register/configuration preservation, and native LW/SW
memory transport at RV32 boundaries. Complete public-decoded ADD, LW and SW
fixtures execute the original Sail clauses through native register/memory effects,
nextPC preparation and PC retirement. Fixtures include an aliased LW rs1/rd update
and an original discarded ADD reading nonzero sources while native operands are zero.
Two dependent ADDs also check actual Sail 0→4→8 retirement despite reversed
witness row order. A complete 32-register public-image fixture exercises the
general trace claim and its terminal values. Boot-profile tests retain public ROM bytes and reject nonzero initial GPRs and invented RAM seeds. A complete native ROM-load fixture checks zero shadow tokens, nonzero public bytes, the actual Sail register result and PC retirement; physical ROM bytes cannot replace the native seed.
The discarded-load fixture also checks an accepted native trace for which the
original Sail instruction fails under the current sparse public-memory boundary, while the documented Airbender NOP profile reaches the native terminal state.
Complete native comparison fixtures check all four forms against -1, deriving reads from public initialization and actual Sail decoding, with destination/source aliases and PC 0→4 retirement.
Native branch fixtures derive source reads from public initialization and logical history for all six opcodes, with backward targets, taken/not-taken paths, signed/unsigned disagreement and wraparound.
The general jump-family trace claim derives every admitted row clause and terminal read; an aliased JALR fixture starts from the unchanged public state and reaches its native terminal PC. Shared composition also checks the existing reversed, dependent two-ADD trace.
Changed project modules pass warning-as-error checks. Audited dependencies use
only standard Lean axioms (`propext`, `Classical.choice`, `Quot.sound`), with no
`sorry` or project axioms. See [reproduction commands](README.md#reproduce),
[trust boundaries](TRUST_AND_REVIEW.md) and the [plan](FORMAL_VERIFICATION_PLAN.md).
