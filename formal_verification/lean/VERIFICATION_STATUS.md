# Verification status

This is the current state, not a change log. Update it after each completed task.
**Checked** means Lean proves soundness of the imported richer no-cache constraints,
under the interfaces stated in `Review/`. It does not mean full prover/verifier soundness.
Standard instructions use pinned Sail; custom operations use the pinned project spec
or the named Clean reference. Controller claims concern explicitly modeled setup rows.
Clean is the sole constraint semantics. Fetch binding is part of the approved
restricted-subset work; interrupts and exceptions remain outside that claim.

## Machine checking

All published claims are kernel-checked. The full-family baseline has 98 importer
checks and 568 audited declarations. The focused trace targets have twenty-two
importer guards, normal/rollover and native-history/rejection/reordering fixtures,
including interleaved per-address histories and rejection of a locally valid
fabricated read value, nonzero initial-value histories and bounds, native Sail
initial-image/byte-order and missing-cell/PC fixtures, public-byte decoding and
missing-byte/wrong-selector rejection, a complete accepted row's decoder binding,
canonical native address bounds and rejection of a noncanonical pair with the same
combined address value, modeled ROM byte reads and wrong-value/missing-address
rejections, a merged history with reordered dependent instructions, and 203 audited declarations.
Changed clock/port/history/path modules pass warning-as-error checks. All audited dependencies are
standard Lean axioms (`propext`, `Classical.choice`, `Quot.sound`); no `sorry` or
project axioms. See [reproduction commands](README.md#reproduce)
and [trust boundaries](TRUST_AND_REVIEW.md). The [plan](FORMAL_VERIFICATION_PLAN.md)
sets the implementation order; this document records the current coverage and gaps.
