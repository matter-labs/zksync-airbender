## Appended setup construction

The no-argument constructor returns `type(GkrWhirVerifierCode).runtimeCode || setup data`. Glamsterdam's EIP-7954 code-size limit permits this single-contract layout; verification reads setup with `codecopy`, without an external data contract. The registry is a generated constant and requires regeneration when changed.

The setup starts at `codesize() - SETUP_DATA_BYTES`: Solidity metadata is inside the runtime prefix, so its length cannot shift these tail-relative reads. A toolchain that appends bytes after the constructor's returned array breaks this assumption; `test_embedded_setup_matches_reference` checks exact deployed prefix and setup bytes, and `test_rejects_shifted_setup` rejects a displaced tail. Changing setup length without regenerating breaks offsets; the generator's pinned payload hash/length assertions, the deployed hash/length check, and the canonical proof test cover that mismatch. `test_rejects_altered_setup_data` separately covers frontier, cap and term-table corruption.
