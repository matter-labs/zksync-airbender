# L1Wrap 2^21 EVM harness

This harness uses the committed 2^21 layout and `l1_wrap_2p21` prover config.
Its proof and aux inputs are
`prover/unified_circuit_proof_proth120_2p21.json` and
`prover/unified_circuit_proof_proth120_2p21_commitment_mod_aux_data.json`.
The expected final PC comes from the committed L1Feeder verifier binary and
must equal the proof aux final PC; the pinned inits/teardowns top bits must
equal the proof's.

Every registered version requires its committed proof and aux inputs. Missing
either input fails the Rust drift checks and explicit generation.

## Merged verifiers

One `GkrWhirVerifier` contract verifies GKR and WHIR in one transaction: tx
calldata = GKR stream ‖ WHIR proof stream, the GKR→WHIR start state handed over
in memory. On success it reports `(publicInput, auxInput, setupCommitment)` to
the `IVerificationRegistry` pinned at construction and returns the same tuple
(registers x10..x17, x18..x25, keccak256 of the setup cap).

- `merged/src/GkrWhirVerifier.sol`: v0 calldata (`debug_data/l1_wrap_2p21/merged_calldata.hex`).
- `merged_f1/src/GkrWhirVerifier.sol` and `SetupFrontier.sol`: format F1
  (`verifier_evm::encoding`, `single_tx_f1.hex`): GKR round polynomials as 2 of 4
  coefficients, WHIR sumcheck steps as 2 of 3, 123-bit element runs, 19-bit
  timestamp limbs, `digest_bytes`-byte Merkle digests; the final PC and the setup
  cap are deployment constants. The pinned `SetupFrontier` data contract (address
  and code hash, checked before any read) holds the setup frontier where setup
  paths stop, the setup cap and the GKR term table. The GKR half decodes its
  section once into a memory image of the v0 GKR calldata; the WHIR half reads the
  F1 stream.
- `negative/{v0_wrong_final_pc,f1_wrong_final_pc,f1_wrong_setup_cap}`: test-only
  controls, each differing from its verifier only in the pinned final PC or setup
  (`f1_wrong_setup_cap`: one frontier node and the cap it reduces to, with its own
  `SetupFrontier.sol`).
- `controls/f1_cap_level`: the F1 verifier without a setup frontier (setup paths to
  the cap; `single_tx_f1_cap_level.hex`) and its `SetupFrontier.sol`.
- `instrumented/{v0,f1}`: oracle renders that log every non-Merkle keccak256
  result and return `[count][hashes][statement]` instead of calling the registry.

All sources are generated by the `generate_contracts` ignored test and checked
by `checked_in_contracts_are_current`. `merged/` holds the static `TestRegistry`
and the Foundry tests: `Merged.t.sol` (v0, incl. registry hardening and
non-canonical lane rejection), `F1Merged.t.sol` (F1 against v0, mutations of every
field kind, setup data binding) and `F1Oracle.t.sol` (equal logs and statements),
plus EIP-170 runtime-size tests. The mutation tests read the semantic offsets in
`calldata_fields.json` / `single_tx_f1_fields.json`.

From the repository root, with Foundry on `PATH`:

```sh
AB_EVM_VERSION=2p21 cargo test -p verifier_evm --release --test generate_contracts -- --ignored
AB_EVM_VERSION=2p21 cargo test -p verifier_evm --release --test flatten_calldata -- --ignored
cargo test -p verifier_evm --release
verifier_evm/generated_contracts/run_merged.sh 2p21 --no-gas
verifier_evm/generated_contracts/run_merged.sh 2p21 <task-owned-anvil-port> <out.json>
```

The gas run (`merged_gas.py`) first deploys every contract with plain CREATE
transactions on an Osaka anvil with EIP-170 enforced (the deployment gate), then
measures one raw transaction per verifier, checking every receipt against
`21000 + max(exec + 4·tokens, 10·tokens)` and recording execution, the registry
frame and the computed Glamsterdam (`15000 + max(4·tokens + exec, 64·bytes)`)
and Hegota (`96·bytes`) prices with the Glamsterdam floor room. A verifier that
the gate rejects is measured with the code-size limit disabled (recorded).
`deploy.sh` / `send_proof.sh` deploy the v0 verifier through CreateX and send
its proof.
